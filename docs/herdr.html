Herdr setup guide

Everything this repo changes or adds on top of stock herdr: the sidebar, the recent-sessions picker, the summarizer plugin, key bindings and the other plugins. Open it with open ~/dotfiles/docs/herdr.html.

The terminal figures are drawn from the real layout with made-up sessions. They are not captures, so nothing from a real session is stored here.

Statuses and dots

Two systems show state, and they answer different questions.

The summarizer's status: where is the work?

StatusMeaning
staleUntouched for a week longer than your newest session. Each stale session is reviewed once by a stronger model against your other sessions, and again only if it moves.
youNeeds you: a decision, information, a review, an action only you can take, or a go-ahead.
workingThe agent is mid-task. A working session that has been silent for 2 hours is shown as idle.
idleStopped without a clear ask; unclear whether anything is left.
finishedThe work was explicitly wrapped up.

herdr's dot: what happened with the last turn?

herdr stateMeaning
doneFinished a turn you have not looked at yet. Becomes idle once you focus the pane.
idleAt the prompt, and you have seen its last turn.
workingMid-turn right now.
blockedStopped at an approval or question dialog.
unknownherdr cannot tell: the agent just started or is gone.

herdr's done is not the summarizer's finished. A session can have an unseen turn and plenty of work left. The orange label is where the two meet: status you plus herdr state done.

How updates happen

Nothing runs on a timer. The plugin subscribes to four herdr events and the rest follows from them.

  1. herdr fires an event. pane.agent_status_changed (a turn started or ended), pane.agent_detected, pane.moved or pane.focused.
  2. The hook returns at once. plugin/hook runs herdr-summarize event, which marks the session dirty and starts a detached worker. herdr waits about 70 ms and never on a model.
  3. The worker checks for a diff. A session is skipped if its transcript file is unchanged, if the new entries are only tool calls, or if the agent is still mid-turn. A pass with nothing new makes no model call.
  4. A small model reads the new turns. Haiku gets the previous label and description plus only the new conversation, and returns the status, who it is waiting on, and your next move. These always follow the latest turn.
  5. The summary changes only when it should. Label and description are rewritten when the new conversation is at least 1,500 characters and the model judges it material, or when work finishes or reopens. Otherwise they stay word for word.
  6. Tokens are published. The label, heat and stale mark go to herdr as pane and workspace tokens, which the sidebar rows in config.toml display.
  • Heat and stale need no timer. They depend on the clock, but only matter while you are looking, and switching panes fires pane.focused.
  • Links come from the parent's transcript. herdr events do not say who started a pane, so the summarizer reads the herdr agent … commands a session ran. Agent names are remembered, so a moved or restarted agent stays nested.
  • Nothing is sent to a running agent. Transcripts are read from ~/.claude/projects; the only writes are herdr tokens and the state folder.
  • Cost. One Haiku call per finished turn that has new conversation, and one Opus call per stale session (at most two per pass).

Install and check

./bootstrap.sh                       # stow config and scripts, install plugins and the Claude integration,
                                     # then run validate.sh -q
./herdr-summarizer/install.sh        # opt in to the summarizer (checks herdr, claude, fzf and a claude login)
./herdr-summarizer/install.sh --uninstall
./validate.sh                        # read-only: is everything linked, loading and actually in use?

After editing config.toml, run herdr config check before reloading with prefix shift+r. The check is what catches mistakes; a reload on its own can report success for a config that has problems.

Troubleshooting

SymptomLook at
No labels at allIs the plugin linked? herdr plugin list. Then ./validate.sh, which checks the link, recent hook runs and the worker log.
Labels never updatetail ~/.local/state/herdr-summarizer/events.log should show queued lines as turns end. ignored (guard) means a leftover test file: delete ~/.local/state/herdr-summarizer/only-sessions.
A pass fails~/.local/state/herdr-summarizer/worker.log, and herdr plugin log list --plugin herdr-summarizer for the hook itself.
One pane has no descriptionThe Claude integration must be installed so herdr knows the session ID. A session also gets nothing until its first turn ends.
Want to see it runherdr-summarize does one pass by hand. herdr-summarize list and herdr-summarize show <pane> print what the picker shows.

Knobs, all environment variables read by herdr-summarize: HERDR_SUMMARIZER_STALE_DAYS (default 7), HERDR_SUMMARIZER_STATE (another state folder), HERDR_SUMMARIZER_DRY (a pass with no model calls). The plugin runs with herdr's environment, so set them there or use them for runs by hand. Each named herdr session keeps its own state under sessions/<name>/. Sessions idle for 30 days are forgotten.

Limits worth knowing

  • Claude sessions only. Summaries come from Claude Code transcripts; other agents show herdr's dot but no label. Proposed: docs/proposals/herdr-summarizer-other-harnesses.md.
  • Links need names. An agent is nested only if its parent drove it through herdr agent commands by name. Agents you start yourself in a new pane are top level.
  • herdr styles tokens statically. A token's colour is fixed in config.toml, which is why the orange label is a second token ($summary_you) sharing a slot with $summary. herdr also always puts · between tokens on a row.
  • The plugin registry is shared by all herdr sessions. A named session (herdr --session sandbox) gets its own server and state, but the same plugins. To test a plugin change safely, list the session names it may act on in ~/.local/state/herdr-summarizer/only-sessions, and delete the file afterwards.
  • Stale is relative. It compares each session with your newest one, so a week away from the machine does not turn everything stale.
Source of truth is the code: herdr/.config/herdr/config.toml, herdr/.local/bin/herdr-summarize (its header and help text) and herdr-summarizer/. Update this page when those change.
